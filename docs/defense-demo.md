# 答辩演示脚本（5–8 分钟）

> 目标：让老师在一屏内看到「选车 → 配置 → 透明报价 → 下订/支付 → 订单/后台」的完整闭环。
> 线上：**https://ziphare.me/**（Cloudflare + Let's Encrypt；IP `http://203.0.113.10/` 只兜底、不能登录）。本地：`pnpm dev` 后 http://127.0.0.1:5173。

## 演示前 2 分钟检查

```bash
curl --max-time 8 https://ziphare.me/api/health
curl --max-time 8 -o /dev/null -w '%{http_code}\n' https://ziphare.me/
```

- 浏览器统一用 https://ziphare.me/ 开两个标签：前台首页、后台 `/admin`。不要用 IP 登录。
- 演示账号：`demo@wangshu.test` / `（演示口令，见现场）`；管理员：`admin@wangshu.test`（口令见本机 `.secrets/admin-password`，不入库）。
- 配置器全系共用 s7 四门轿车 3D 示意模型，封面用高清海报；右上角可切 2D 高清海报（不加载 3D），3D 失败也会回退海报。
- 若网络不稳：直接切本地 `http://127.0.0.1:5173`，数据是本地 SQLite，功能一致。

## 流程

### 1. 首页（30s）

- 停在 hero：广告式车型轮播（6 秒自动切换），主 CTA「了解我们」。
- 向下滚动：数字条、海豹 / 汉 EV 两张车型卡、技术区、购车流程、服务/新闻。
- 一句话：**这不是一张静态海报，后面的配置、价格、订单都是真的。**

### 2. 选车向导 / 对比（40s）

- 点「选车」→ 三个问题：预算 30–60 万、驾驶乐趣 → 推荐海豹。
- 打开「车型对比」：海豹 / 汉 EV 的起售价、续航、零百、功率一张表。
- 点顶部「海报」：20 张跨品牌官方海报（BYD + 特斯拉/小鹏/极氪/小米/蔚来/理想/问界/零跑/埃安），切「轿车 / SUV / 发布会」，点开灯箱；说明这是车型视觉基准。
- 一句话：**系统先帮用户缩小范围，而不是直接丢一张参数表。**

### 3. 配置器（2–3min，重点）

- 进入海豹配置器（车型照片 + 选项面板）。
- 依次切：版本（标准/长续航/赛道）、车漆（月岩灰/深海蓝）、轮毂（19/21 英寸）；照片不变，价格与选项状态实时联动。
- 故意选 21 英寸轮毂 + 标准版 → 出现「需搭配高性能版本」业务错误，价格条不可下订。
- 切赛道版 → 恢复可下订。
- 展示白底官网、车型卡与「了解我们」公司页。
- 一句话：**规则和价格都在服务端算，前端只传选项 ID；不是把价格写死在页面上。**

### 4. 报价单 / 下订 / 模拟支付（1–2min）

- 点「生成报价单」→ 裸车、购置税、保险、上牌、落地逐项列明。
- 点「立即下订」→ 填姓名/手机/门店 → 生成订单号。
- 点「模拟支付」→ 页面明确标注「演示环境 · 模拟支付」，不产生真实扣款。
- 一句话：**支付是模拟的，但订单状态机、金额快照和幂等支付是真的。**

### 5. 我的账户 / 订单（30s）

- 登录 demo 账号 → `/account` 看到两笔订单（已确认/已支付）。
- 点订单 → 状态时间线、配置快照、金额。
- 一句话：**订单和用户绑定，刷新/重登不会丢。**

### 6. 管理后台（1min）

- 登录 admin → `/admin`：概览（订单/收入/线索）、订单（确认/交付/取消）、试驾线索。
- 切「车型价格」：版本指导价可改；切「门店」：电话/地址/营业时间可改。
- 一句话：**前台展示、交易、后台运营是同一套数据，不是两张皮。**

## 可能被问的问题

| 问题 | 回答要点 |
|---|---|
| 为什么金额用「分」？ | 避免浮点误差；所有价格/规则在 `packages/shared/pricing.ts`，API 重算，前端不信任。 |
| 车型图哪来的？ | 封面海报来自比亚迪官网公开素材；3D 配置器共用 MMC Works Generic Sedan（CC BY 4.0）四门轿车模型；页脚/CREDITS 保留署名。 |
| 为什么不用 Java/MySQL？ | 项目是单机演示规模，Node/Fastify + SQLite 更轻、部署简单；论文里写清选型理由与边界。 |
| 3D 还做吗？ | 做。配置器所有车型/版本共用同一个四门轿车 3D 模型（s7.glb，GLTF/KTX2/车漆/轮毂），封面仍用高清海报；3D 是选配视觉，海报是车型封面。 |
| 和普通商城有什么区别？ | 车型/版本/选装/规则/税费/保险/上牌/门店/试驾是汽车业务对象；配置器有合法性规则与图片展示，不是 SKU 列表。 |
| 支付真的吗？ | 不是。显著标注模拟支付，只写 payments 记录，不对接商户；论文中说明这是演示边界。 |
| 并发/性能？ | 单机 SQLite + WAL；演示规模足够；车型图静态加载；后续可换对象存储/CDN。 |
| 下一步？ | HTTPS/域名、内容管理、订单退款、模型压缩/CDN、更多车型。 |

## 兜底

- 图片加载失败：配置器保留文字与选项面板，功能不受影响。
- 线上 502：`ssh deploy@203.0.113.10 'systemctl status wangshu-api'`；重启 `sudo systemctl restart wangshu-api`。
- 线上数据乱了：用 `/opt/wangshu/backups` 最近备份恢复；或本地 `pnpm --filter @wangshu/api db:seed` 重置本地。
- 演示前不要跑 `db:seed`，会清空线上演示订单/线索。

> 车鉴 CarLens 多品牌汽车配置聚合与在线报价平台（毕业设计，非官方网站；当前演示车型数据以比亚迪公开素材为样本）。用户从选车向导或车型对比开始，进入共用四门轿车 3D 配置器选择版本、车漆、轮毂和选装；服务端按规则校验并实时计算裸车、购置税、保险、上牌的落地价；确认后下订、模拟支付，订单进入状态机；运营在后台处理订单和试驾线索。前台展示、交易、后台共用一套 SQLite 数据，已部署在 203.0.113.10。
