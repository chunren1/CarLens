# 毕业设计（论文）选题说明

专业：计算机科学与技术　　届别：2027 届

## 一、拟定题目

主选：《新能源汽车在线配置与报价系统的设计与实现》（20 字）——沿用，按老师意见不改

备选一：《面向汽车销售企业的配置与试驾预约系统设计与实现》（23 字）

备选二：《汽车配置器与透明报价系统的设计与实现》（18 字）

## 二、选题背景与要解决的问题

新能源汽车品牌越来越多采用官方直营、线上下单的模式：用户在品牌官网完成看车、配置、比价、下订，再到门店交付。但实际体验里还有三个断点：配置器只负责好看，选装约束和价格联动不透明；报价单和订单脱节，用户不知道定金付给谁、订单到哪一步；金融方案、门店、试驾信息分散在其他页面。

第三方平台和经销商报价则容易变成“车贩子”式的撮合：同样的车、不同的报价、说不清的费用。品牌官方直营站要解决的不是“多一个卖车入口”，而是把“配置—价格—下订—支付—交付”做成一条可解释、可追踪的链路。

同类毕业设计大多停留在两类：一类是通用“汽车选购系统”（车型列表、详情、收藏），把选车简化为浏览；另一类是通用“商城系统”（商品 CRUD、购物车、订单），和汽车配置无关。两者都没有解决“配置约束 + 透明报价 + 官方直营下单”的组合问题。

本项目做一个虚构新能源品牌“望舒”的官方直营站：以在线配置器为核心，叠加透明报价、在线下订、模拟支付、金融方案、门店与试驾、订单跟踪，后台管理车型、配置、订单、线索与内容。题目沿用“在线配置与报价”，但系统在报价之后补上了下订、模拟支付与订单跟踪，把“卖车”作为功能延伸，而不是另起一个经销商报价工具。

## 三、主要研究内容

1. 车型与配置数据建模：品牌、车系、版本、车漆、轮毂、内饰、选装包、可用性与约束规则，共 17 张表。
2. 配置约束与价格引擎：requires、excludes、minTrim 三类规则；服务端权威校验；配置变化对价格、续航、加速的联动；落地价模型（购置税减半与上限、保险估算、上牌）参数化。
3. 在线配置器：左侧车辆呈现、右侧选项、底部价格条；换漆、换轮毂、选装实时反馈；保存配置并生成分享链接。
4. 官方直营购车流程：报价 → 下订（选交付门店、确认配置快照与定金）→ 模拟支付网关 → 订单状态机（待支付、已支付、已确认、已交付、已取消）→ 订单跟踪。
5. 金融方案计算器：首付比例、期数、年化利率，实时计算月供、总利息与总还款。
6. 门店查询、预约试驾与线索管理：门店列表与筛选、试驾预约、销售线索状态流转。
7. 内容与后台：车型/配置/订单/线索/门店/参数管理、数据看板；品牌故事、新闻、车主服务等内容页。
8. 工程实现与部署：Vue 3 + TypeScript 前端，Node.js + Fastify + SQLite 后端，Docker + nginx + Cloudflare 隧道部署，自动化测试与 CI。

## 四、技术路线与工作量

技术路线：前端 Vue 3 + TypeScript + Vite；后端 Node.js 22 + Fastify + Drizzle ORM + SQLite；后台管理使用 Element Plus；部署采用 Docker 容器 + nginx 静态托管 + Cloudflare 隧道，构建全部在本地完成，服务器只运行产物。

工作量：4 款车型、17 张数据表、16 个以上接口、订单与支付状态机、规则与价格引擎、金融计算器、门店与内容页、后台 CRUD 与看板；配套单元测试、接口测试与端到端测试。论文按“需求分析—系统设计—系统实现—系统测试—部署”组织，正文不少于 8000 字。

支付说明：系统只做模拟支付网关（跳转页面），不接入支付宝/微信商户，不产生真实扣款；页面显著标注“演示环境 · 模拟支付”，论文中作为“支付流程与订单状态机”的设计验证，不涉及真实资金。

进度安排：2026 年 11 月完成视觉与交互定稿；12 月完成公网站点；2027 年 1 月完成配置器与报价；2 月完成购车闭环（订单、模拟支付、金融、门店）与后台；3 月上线并冻结功能；4 月完成论文初稿；5 月答辩演练；6 月答辩。

## 五、与以往题目的区别

对提供的 651 条历史题目做了关键词比对：

- 含“配置”“选配”“报价”“试驾”“4S”“新能源”“支付”“直营”“购车”的题目均为 0 条；
- 含“汽车”的题目 6 条：2 条汽车租赁、1 条汽车玻璃商城、1 条汽车护理用品商城、1 条家用汽车选购系统、1 条汽车租赁小程序；
- 含“选购”的题目仅 1 条，即“家用汽车选购系统的设计与实现”，是通用选购站（列表、详情、收藏），没有配置约束、实时价格、订单与支付闭环；
- 含“商城”的 48 条、含“销售”的 14 条，都是通用电商/商品销售系统，与汽车配置无关；含“订单”的 2 条是外卖订单管理，含“订购”的 1 条是通用在线订购。

本题目研究的是“官方直营 + 配置约束 + 透明报价 + 下订/支付/订单”的组合，与上述题目的问题域不同，不构成重复。

## 六、预期成果

1. 一套可运行、可演示的官方直营购车系统：品牌官网、在线配置器、透明报价、在线下订、模拟支付、订单跟踪、金融方案、门店与试驾、后台管理，部署在公网。
2. 毕业论文一篇（正文不少于 8000 字），包含需求分析、系统设计、关键实现、系统测试与部署。
3. 配套材料：设计文档、接口文档、测试报告、演示脚本与演示视频。

## 七、需要与老师确认的三点

1. 题目是否必须绑定具体单位或企业？本项目为面向新能源汽车品牌官方直营场景的自主开发，暂无委托单位，系统以虚构品牌“望舒”的示例数据演示；若必须绑定，可在不改变研究内容的前提下调整为“XX 汽车销售公司官方直营购车系统的设计与实现”。
2. 支付为模拟网关（跳转页面，不接真实商户、不产生扣款），页面会标注“模拟支付”；请确认论文与答辩中按“支付流程与订单状态机验证”表述是否可以。
3. 三个题目均不超过 25 字；若学院对技术栈有统一要求（如 Java/Spring Boot），后端可在不改前端与数据模型的前提下调整。
